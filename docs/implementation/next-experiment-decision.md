# 다음 대표 실험: 기준선 이후의 결정

상태: 관찰 기록, 새 실험 가설·성공 기준은 미승인

## 확인한 사실

[6,000 Run 기준선](milestone-03-synthetic-players.md), 각 Persona 1,000 Seed에서:

- Novice Stage 3 통과율: 100%.
- Novice 전체 클리어율: 97.2%.
- Greedy 전체 클리어율: 100%.
- Aggressive 전체 클리어율: 95.6%.
- Defensive의 Defense/Sustain 보상 비율: 91.4%, 정규화 선택 엔트로피: 0.795.

이는 실제 인간의 난도·재미 평가가 아니라 현재 Agent 정책과 Config의 결과다.

## 최초 계획에 미치는 영향

최초 계획은 Novice Stage 3 실패가 크다고 가정한 난도 완화 실험이었다. 관측 통과율 100%에서는 8%p 개선이 불가능하다. 단순히 목표를 전체 클리어율로 옮겨도 현재 기준선에서 최대 개선 폭은 2.8%p다.

원래 실험 문서도 이 가정이 나타나지 않으면 관찰 문제를 바꾸도록 규정한다. 다만 새 목표·Agent 수정·밸런스 변경 폭·성공 기준을 결과에 맞춰 임의 확정하지 않는다.

## 소유자가 결정할 내용

다음 대표 실험에서 개선할 문제 하나와 이유를 정한다. 예를 들어 난도 곡선을 재설계하거나, 특정 Persona의 보상 집중과 빌드 다양성을 연구하거나, Novice 정책이 정말 미숙한 플레이를 대표하는지 먼저 보정할 수 있다. 낮은 엔트로피 자체가 나쁜 밸런스라는 뜻은 아니며 Persona 설계 의도와 구분해야 한다.

결정 후 진행 순서:

1. 문제에 맞는 Control과 고정된 Agent Version을 정한다.
2. Primary Metric, guardrail, 변경 폭, 성공 기준을 사전 등록한다.
3. M6에서 Experiment/Variant 관리·비동기 대량 실행·지표 비교 대시보드를 연결한다.
4. M7의 근거 제한 분석과 M8의 사람 승인·게시·롤백을 연결한다.

기술 선택 ADR은 변경할 필요가 없다. React/Vite + ASP.NET Core + PostgreSQL + 별도 Worker 설계는 그대로 유지한다. 공개 배포·AI 유료 호출·카드 등록은 이번 자동 구현에서 수행하지 않았다.
