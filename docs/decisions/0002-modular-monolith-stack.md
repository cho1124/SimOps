# ADR-0002: 전체 배포 단위

상태: 제안

연결 워크숍: [Workshop-0001](../workshops/0001-deployment-unit.md)

## 맥락

SimOps는 플레이 API, 랭킹, 설정, 실험, 분석과 CPU 집약적인 시뮬레이션을 필요로 한다. 개인 프로젝트의 완주 가능성을 유지하면서 책임과 장애 경계를 정해야 한다.

## 고려한 선택지

- 모듈형 모놀리스 API + 별도 Worker
- 기능별 마이크로서비스
- API, Dashboard, Background Job을 포함한 단일 프로세스

## 제안 결정

모듈형 모놀리스 API와 별도 Worker를 사용한다.

Backend 언어, DB, Dashboard, Job 기술은 이 ADR의 결정 범위에서 제외하고 각 워크숍과 ADR에서 선택한다.

## 제안 이유

- 기능 경계를 코드로 구분하면서 배포 복잡도를 제한할 수 있다.
- CPU Simulation을 API 요청 처리와 격리할 수 있다.
- 실제 독립 확장 요구가 생기면 모듈을 분리할 수 있다.

## 결과와 포기한 것

승인 후 프로젝트 소유자의 설명으로 갱신한다.

## 재검토 조건

- 특정 모듈의 독립 배포·확장이 지속적으로 필요함
- API와 Worker의 공유 저장소가 장애 격리를 방해함
- 단일 API 배포가 서로 다른 기능의 릴리스 주기를 막음
