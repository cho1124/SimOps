# ADR-0004: 재실행 검증과 시즌별 단일 설정 랭킹

상태: 승인

## 맥락

클라이언트가 제출한 점수는 조작될 수 있고, 서로 다른 밸런스 설정의 점수를 같은 랭킹에서 비교하면 공정하지 않다.

## 고려한 선택지

- 클라이언트 점수를 그대로 저장
- 결과 상태 일부만 서버에서 검증
- 서버가 시드와 행동 로그로 전체 Run을 재실행

공개 설정:

- 시즌 중 설정을 자유롭게 교체
- 설정별 랭킹을 분리
- 시즌마다 하나의 Game/Config/Score Rule을 고정

## 결정

- 서버가 Run Ticket에 시즌, Game Version, Config, Score Rule, Seed를 고정한다.
- 클라이언트는 순서화된 행동 로그를 제출한다.
- Worker가 동일 Game Core로 재실행하고 서버에서 점수를 계산한다.
- 검증된 인간 Run만 공개 랭킹에 반영한다.
- 한 시즌은 하나의 Game Version, Config Version, Score Rule Version을 사용한다.
- 공개 설정 변경과 롤백은 새 시즌으로 처리한다.
- 합성 플레이어는 인간 랭킹에 등록하지 않는다.

## 이유

- 임의 체력·공격력·점수 조작을 탐지할 수 있다.
- 리플레이와 실패 재현을 같은 데이터로 지원한다.
- 랭킹 참가자가 동일한 규칙에서 경쟁한다.

## 결과와 포기한 것

얻는 것:

- 검증 가능한 랭킹
- 시즌 공정성
- 행동 로그 기반 리플레이

감수하는 것:

- Run 제출 후 비동기 검증 시간이 필요하다.
- 활성 Game Version의 Verifier를 유지해야 한다.
- 공개된 시드를 외부에서 탐색하는 고급 도구 보조 플레이는 완전히 막지 못한다.
- 작은 밸런스 변경도 새 시즌 경계가 필요할 수 있다.

## 재검토 조건

- 실사용 환경에서 검증 비용이 처리량 한도를 넘음
- 여러 설정을 같은 시즌에서 공정하게 비교할 명확한 규칙이 생김
- 강한 안티치트 요구로 서버 권위 진행 방식이 필요해짐
