# ADR-0015: Unity WebGL 프로토타입 추가

상태: 승인

결정일: 2026-08-27

## 맥락

프로젝트 소유자가 설치 없이 브라우저로 게임에 접근하는 방향을 제안하고 진행에 동의했다. 기존 Unity·C# 자산과 LiveOps 학습 범위를 유지한다. 공개 호스팅 사업자 선택·계정 연결은 이번 로컬 구현 승인과 별개다.

## 결정

- Windows·Android를 제거하지 않고 같은 Unity 프로젝트에 WebGL 빌드를 추가한다.
- 게임 화면은 Unity WebGL, 운영 화면은 기존 React/Vite를 유지한다.
- ASP.NET Core API, 독립 Worker, PostgreSQL, 서버 재실행 검증을 유지한다. 서버를 브라우저나 JavaScript로 옮기지 않는다.
- 브라우저는 동일 출처 `/api` 게이트웨이로 플레이어·공개 API에 접근한다. 운영자·승인자 API와 DB는 게임 호스트에 노출하지 않는다.
- 먼저 loopback 전용 로컬 실행과 브라우저 플레이를 검증한다. 외부 공개는 HTTPS·서버/DB·비용·카드 조건을 별도로 검토한 뒤 진행한다.
- 익명 계정과 최신 한 판의 진행은 브라우저 저장소에 보관한다. 네이티브 계정·저장과 자동 연동하지 않는다.

## 이유와 대가

URL로 접근하는 게임 클라이언트와 기존 LiveOps 백엔드의 연결을 학습할 수 있다. 동일 Core의 WebAssembly 실행 결과를 서버 .NET 결과와 비교할 수 있다. 대신 초기 다운로드, 메모리, 브라우저 저장소·수명주기, 기기별 WebGL 호환성 검증이 추가된다.

WebGL 정적 파일만 배포해도 API·Worker·DB가 자동 호스팅되는 것은 아니다. 브라우저 저장소 삭제나 주소 변경 시 진행/익명 계정의 연속성이 깨질 수 있다. 모바일 브라우저 검증은 Android 네이티브 실기기 QA를 대체하지 않는다.

## 재검토 조건

- 모바일 브라우저의 초기 로딩·메모리·입력 품질이 목표에 못 미침.
- 공개 플레이 수요가 생겨 비용 0원·카드 불필요 조건에서 서버 운영이 필요함.
- 계정 연동, 여러 판 보관, 동시 탭 충돌 해결이 실제 요구사항이 됨.
