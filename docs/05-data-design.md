# 데이터 설계

상태: 사전 초안

## 설계 원칙

- 인간, 규칙 기반 봇, 학습형 봇 데이터를 구분한다.
- 게임, 설정, 에이전트, 점수 공식의 버전을 모두 기록한다.
- 집계 결과만이 아니라 재현에 필요한 시드와 행동 로그를 보존한다.
- 랭킹 점수는 클라이언트가 아니라 검증된 서버 결과로 계산한다.
- 분석용 이벤트와 운영용 트랜잭션 데이터를 구분한다.

## 핵심 엔티티 후보

### Player

- 플레이어 식별자
- 닉네임
- 계정 유형
- 생성 시각

### Season

- 시즌 식별자와 이름
- 시작·종료 시각
- 점수 규칙 버전
- 허용 게임·설정 버전

### GameRun

- Run 식별자
- 플레이 주체와 유형
- 게임·설정·에이전트 버전
- 시드
- 결과, 점수, 도달 스테이지, 턴 수
- 검증 상태

### RunAction

- Run 식별자
- 행동 순서
- 행동 유형과 파라미터

### Experiment

- 가설
- 상태
- 시작·종료 시각
- 성공 기준

### ExperimentVariant

- 실험 식별자
- Variant 이름
- 설정 버전
- 배정 정책

### GameConfig

- 설정 버전
- 상태
- 설정 내용
- 승인·배포·롤백 이력

### AgentDefinition

- 에이전트 유형과 버전
- 페르소나 파라미터
- 구현 식별자

### LeaderboardEntry

- 시즌
- 플레이어
- 최고 Run
- 점수와 순위 계산용 값

## 버전 식별자

모든 분석 가능한 Run은 최소 다음 값을 가진다.

```text
gameVersion
configVersion
scoreRuleVersion
agentType
agentVersion
seed
experimentId
variantId
```

## 데이터 계층 후보

- 원시 행동 로그: 재현과 서버 검증
- 텔레메트리 이벤트: 플레이 흐름 분석
- Run 요약: 대부분의 통계 계산
- 사전 집계: 대시보드 및 랭킹 응답 최적화

## 미결정 사항

- 행동 로그 전체 보존 기간
- 원시 이벤트와 요약 이벤트의 경계
- 랭킹 갱신 방식
- 대량 시뮬레이션 데이터 파티셔닝
- 익명 계정 토큰과 개인정보 정책
- 리플레이 포맷과 하위 호환 정책
