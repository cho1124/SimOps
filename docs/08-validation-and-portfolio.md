# 검증 및 포트폴리오 계획

상태: 사전 초안

## 검증 축

### 정확성

- 동일 시드·설정·행동의 결과 일치
- 유효하지 않은 행동 거부
- 클라이언트와 서버 결과 일치
- 점수 공식 버전별 결과 고정

### 실험 신뢰성

- Variant 간 동일 시드 집합 사용
- 에이전트 성향별 선택 분포 확인
- 반복 실험 결과 변동 범위 확인
- 합성 데이터와 인간 데이터 분리

### 성능

- 초당 Run 처리량
- 18,000회 대표 실험 완료 시간
- 이벤트 배치 전송 처리량
- 랭킹 조회 응답 시간

### 멀티플랫폼

- 최소 한 종류의 PC 빌드와 한 종류의 모바일 빌드 설치·실행
- 플랫폼 간 동일 Golden Run의 Result Hash 일치
- 키보드·마우스와 터치로 모든 유효 행동 수행
- 지원 해상도·화면비·Safe Area에서 핵심 UI 접근 가능
- 모바일 일시 중단·강제 종료·복귀 시 Run 손상 없음
- 동일 시즌·설정·랭킹 계약 사용

### 운영 안전성

- 설정 스키마 검증
- 승인되지 않은 배포 거부
- 이전 설정 롤백
- 실패한 배포 이력 확인
- AI의 직접 배포 차단

### 보안과 악용

- 임의 점수 제출 거부
- 조작된 행동 로그 거부
- 잘못된 버전·시드 요청 거부
- 운영 API 권한 분리

## 대표 데모 시나리오

1. 사람 플레이를 랭킹에 제출한다.
2. 서버가 행동 로그를 재실행하고 점수를 검증한다.
3. 운영자가 중반 난도 문제를 발견한다.
4. Control과 두 Treatment를 만든다.
5. 합성 플레이어가 총 18,000회 플레이한다.
6. 대시보드와 AI 분석가가 결과를 설명한다.
7. 운영자가 설정 하나를 승인하고 배포한다.
8. Unity 클라이언트가 새 설정을 적용한다.
9. PC와 모바일 빌드에서 동일한 공개 설정과 랭킹을 확인한다.
10. 필요하면 현재 시즌을 종료하고 이전 설정으로 새 시즌을 시작한다.

## 포트폴리오에서 보여줄 역량

- Unity와 게임 시스템에 대한 기존 깊이
- 하나의 Game Core를 공유하는 PC·모바일 클라이언트 구조
- 엔진 독립적인 결정론적 게임 코어 설계
- 합성 플레이어와 대량 시뮬레이션
- 백엔드 API와 서버 검증
- 데이터 모델링과 분석
- 웹 운영 대시보드
- LiveOps 승인·배포·롤백
- 근거 기반 AI 활용과 권한 통제
- 시스템 전반의 테스트와 관측

## 공개 자료 후보

- 2~3분 프로젝트 데모
- 전체 아키텍처 그림
- 첫 Control/Treatment 실험 보고서
- 사람과 합성 플레이어 비교 결과
- 재현 가능한 실패 Run과 리플레이
- 주요 ADR 3~5개
- 성능 및 검증 결과
- 합성 데이터의 한계와 회고

## 핵심 설명

> Unity 게임 개발 역량을 기반으로 게임 규칙을 Headless 시뮬레이션 가능한 구조로 분리하고, 성향이 다른 합성 플레이어의 대량 플레이 데이터를 백엔드와 웹에서 분석했다. 밸런스 변경안을 사전 실험하고, 사람의 승인 후 Remote Config로 반영하며, 행동 로그 기반 서버 검증과 롤백이 가능한 LiveOps 폐루프를 구현했다.
