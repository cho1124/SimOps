# 실험 및 측정 기획

상태: 초안

## 목적

합성 플레이어를 실제 사용자 데이터의 대체재로 단정하지 않고, 밸런스 가설·회귀·극단적 전략을 반복 가능한 조건에서 탐색한다.

## 첫 번째 실험 초안

### 관찰 문제

초보자 성향의 플레이어가 중반 스테이지에서 과도하게 실패한다.

### 가설

적 공격력을 직접 낮추는 방식보다 중반 이전 회복 선택지를 늘리는 방식이 전체 난도를 완화하면서 빌드 다양성을 덜 훼손한다.

### Variant

- A: 중반 스테이지 적 공격력 감소
- B: 중반 이전 회복 보상 출현 확률 증가

정확한 수치는 기준 밸런스 플레이 후 정한다.

### 실행 구성

- 합성 플레이어: 최소 5종
- Variant: A와 B
- 반복 횟수: 페르소나·Variant별 1,000회 초안
- 모든 실행에 시드, 설정 버전, 게임 버전, 에이전트 버전을 기록한다.

## 핵심 지표 후보

### 결과 지표

- 전체 및 페르소나별 클리어율
- 최고 도달 스테이지
- 스테이지별 실패율
- 평균·중앙 플레이 턴 수
- 종료 시 남은 체력

### 다양성 지표

- 행동 선택 분포
- 보상 선택 분포
- 빌드 조합 수
- 특정 행동·보상 집중도

### 가드레일 지표

- 무한 또는 과도한 전투 길이
- 특정 조합의 비정상 승률
- 유효하지 않은 상태 전이
- 에이전트별 행동 불능률
- 설정 검증 실패율

### 시스템 지표

- 초당 시뮬레이션 수
- 한 Run 평균 처리 시간
- 이벤트 배치 크기
- 서버 검증 실패율

## 이벤트 후보

- `run_started`
- `encounter_started`
- `action_selected`
- `reward_offered`
- `reward_selected`
- `encounter_ended`
- `run_ended`
- `validation_failed`
- `error_detected`

이벤트의 필드와 저장 전략은 시스템 규칙과 지표가 확정된 후 데이터 설계에서 결정한다.

## AI 분석 원칙

- 지표 계산은 쿼리 또는 분석 코드가 담당한다.
- AI에는 계산된 결과와 제한된 메타데이터만 제공한다.
- AI 설명에는 사용한 지표와 비교 기준을 포함한다.
- AI 제안은 자동으로 운영 설정에 반영되지 않는다.
- 분석 결과에는 합성 데이터임을 표시한다.

## 인간 데이터가 생긴 이후

- 사람과 합성 플레이어를 별도 집단으로 저장한다.
- 점수, 선택, 실패 구간의 분포 차이를 비교한다.
- 실제 인간 로그로 페르소나 파라미터를 보정할 수 있다.
- 보정 전후 에이전트 버전을 분리한다.
- 실제 사용자 수가 적을 때 통계적 확신을 과장하지 않는다.

## 미결정 사항

- 각 지표의 목표 범위
- 성공·실패를 판단하는 종합 기준
- 빌드 다양성 계산 방법
- 시드 배정과 A/B 공정성 방식
- 반복 횟수 결정 기준
- 실제 사람 플레이와 합성 플레이 비교 기준
